# 節慶小遊戲共通規格

四個現有遊戲使用 `common.js`、`common.css`；後續端午、七夕、中秋、國慶沿用同一份流程。

| 遊戲 | 完成條件 |
| --- | --- |
| 萬聖節 | 三關限時 10／10／20 秒；各關找齊 5 隻普通幽靈或時間到即換關／結算，金色幽靈不列入過關條件；無提示按鈕，保留第三關場景線索 |
| 聖誕節 | 40 秒，維持一般／進階模式與答題閘門 |
| 春節 | 第一關 20 秒，自動進入第二關；3 隻小年獸各 5 次、大年獸 20 次有效命中 |
| 兒童節 | 40 秒；時間到停止新操作，完成已發射箭矢後結算 |

- HUD：左上離開、中央時間或任務進度、右上貨幣／收集數；聲音按鈕固定在右側第二列。倒數整數秒，最後 10 秒轉紅。
- 不提供暫停；離開確認視窗不停止遊戲。限時關卡使用實際經過時間，切回分頁不延長時限。
- 每局經過「遊戲結束」畫面，才顯示結算並回報。主頁確認後開放再玩和返回；同一局重送不重複發獎。
- 載入與閱讀說明不扣次。按開始由主頁檢查開放狀態、扣次／體驗費；中途離開不發獎、不退已用次數。
- 再玩須回主頁檢查資格並建立新局。正式活動回對應活動頁；體驗回星宮；獨立試玩離開回 `../../index.html`。
- 體驗每遊戲每日 3 次，每次 50 星星糖，無正式獎勵。正式次數維持各遊戲設定。
- 全部音訊輸出接 `FSGame.output(audioContext)`，共用限幅與靜音設定。實際聽感仍須在同裝置試聽校準。

## 獎勵平衡基準

每日收入暫以 120～150 為目標，男女兩套造型＋一間共用小屋約 5～9 天收齊。這是規劃目標，仍須一般玩家試玩校準，不保證每局收入。

| 節慶 | 每日場次 | 每套造型 | 共用小屋 | 男女全套總價 | 完成獎勵 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 萬聖節 | 3 | 240 | 300 | 780 | 無，依找到的幽靈計算 |
| 聖誕節 | 5 | 200 | 300 | 700 | 10 聖誕襪，另計禮物所得 |
| 春節 | 3 | 280 | 380 | 940 | 擊退大年獸給 5～10 紅包；大年獸每次命中 0～1 紅包 |
| 兒童節 | 3 | 220 | 320 | 760 | 8 彩票，另計射擊所得 |

完成獎勵也納入畫面合計與單次入帳；體驗模式只展示，不發正式貨幣。中途退出沒有完成獎勵。

新增節慶先列：玩法、完成條件、遊玩時間、每日場次、獎勵來源、失誤扣除，以及新手／一般／熟練表現假設。以「男女全套總價 ÷ 每日平均收入」檢查收集天數，再各收集至少 10～20 局試玩資料，記錄遊戲模式、完成時間、各來源收入、失誤扣除、合計與完成率，修正假設。完成局與中斷局分開統計。

`node balance-festivals.cjs` 會依現有價格與明列的表現假設產生模擬報告，供新增遊戲比較；報告不是人類玩家實測結果。

## 主頁與小遊戲訊息

每局 URL 帶 `session`。雙方檢查訊息來源、origin、session；主頁另核對遊戲鍵。

1. 小遊戲 `fsGameStart` → 主頁檢查並扣次 → `fsGameStarted`。
2. 完成畫面後 `fsGameResult`（`completed: true`、整數 `earned`）→ 主頁單次入帳 → `fsGameSettled`。
3. `fsGameReplay` 建立新局；`fsGameClose` 關閉 iframe 並返回正確入口。

這是既有前端存檔架構的局次核對，不是伺服器反作弊驗證。

## 驗證

在專案根目錄執行 `node verify-festivals.cjs`。需要 Playwright 與 Microsoft Edge；可使用 Codex 隨附的 Playwright。
測試以替代主頁狀態檢查四個實際遊戲 iframe，包含手機 HUD、時間、命中次數、入帳、再玩、體驗扣款及離開；截圖存於 `artifacts/festivals/`。
