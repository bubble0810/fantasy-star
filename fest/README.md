# 節慶小遊戲共通規格

八個節慶遊戲（含七夕、中秋、國慶）使用 `common.js`、`common.css`，由主頁統一處理扣次、入帳、體驗及重玩。

## 開頭說明頁

八個遊戲另載入 `intro.js`、`intro.css`，只統一開始前的說明畫面。各節慶的精簡文案與詳細規則集中在 `intro.js`，配色集中在 `intro.css`；修改玩法時須同步檢查這份說明。

- 結構：模式標示、節慶小標、遊戲名稱、一句玩法、明示關卡數、核心規則、可展開的詳細規則與獎勵。聖誕模式選擇保留在說明區最上方。
- 實際顯示字級：主標 28px、分區標 18px、核心內文 16px、補充與詳細規則 14px。七夕按舞台縮放反向補償，避免文字縮小。
- 只捲動中間說明區；下方左側返回、右側開始，同列且皆高 50px。正式顯示「開始活動」，體驗顯示「支付並開始」，獨立開啟顯示「開始遊戲」。主按鈕 18px、返回 16px，避免手機文字換行。
- 正式活動返回活動頁，體驗返回星宮體驗館，單獨開啟則返回主頁。開頭返回不扣次、不收體驗費。
- 版型與字體一致，各節慶保留獨立標題色、主按鈕色、邊框與底色。只移動原有按鈕及模式節點，不更換已綁定的操作事件；進入遊戲即解除說明頁專用樣式。
- 發布需包含根目錄 `festgames.js`、`fest/common.js`、`fest/intro.js`、`fest/intro.css` 與八個遊戲更新後的 `index.html`。不改商店價格或各遊戲玩法、獎勵程式。

`node artifacts/intro-review/audit.cjs` 可檢查八個遊戲的說明、手機按鈕、正式／體驗返回與開始銜接；本機截圖及檢視資料在 `artifacts/intro-review/`。

- HUD：左上離開、中央時間或任務進度、右上貨幣／收集數；聲音按鈕固定在右側第二列。倒數整數秒，最後 10 秒轉紅。
- 不提供暫停；離開確認視窗不停止遊戲。限時關卡使用實際經過時間，切回分頁不延長時限。
- 每局經過「遊戲結束」畫面，才顯示結算並回報。主頁確認後開放再玩和返回；同一局重送不重複發獎。
- 載入與閱讀說明不扣次。按開始由主頁檢查開放狀態、扣次／體驗費；中途離開不發獎、不退已用次數。
- 再玩須回主頁檢查資格並建立新局。正式活動回對應活動頁；體驗回星宮；獨立試玩離開回 `../../index.html`。
- 體驗每款每日最多 3 次，依序收 100／200／500 星星糖；各款分開累計、每日重置，不發活動獎勵且不占正式活動次數。正式次數維持各遊戲設定。
- 體驗館頂部只顯示每日上限；卡片顯示「查看遊戲・剩餘次數」，不跳瀏覽器確認視窗。資訊頁顯示本次次序、費用、目前餘額，按支付並開始才扣款；取消不扣。餘額不足可看玩法，但不能開始。
- 確認頁開著時，費用或日期改變會更新資訊並要求再次確認，不直接扣除新費用；開始前再驗正式活動日期、剩餘場次與體驗餘額。進入體驗後不會因節慶日期改變而切為正式活動。
- 八大識別配色：萬聖粉橘／黑、聖誕白／淺藍、春節紅／粉黃、兒童粉綠／粉黃／淺藍、端午淺綠、七夕粉紅／深紫、中秋粉紅／粉黃、國慶白／藍／紅／綠；淺色用作底色，文字及按鈕採較深同色系。

`node verify-trial-pricing.cjs` 驗證八款階梯收費、取消、再玩、餘額不足、確認資訊更新、每日重置與正式活動分流。
- 全部音訊輸出接 `FSGame.output(audioContext)`，共用限幅與靜音設定。實際聽感仍須在同裝置試聽校準。

## 獎勵平衡基準

每日收入暫以 120～150 為目標，男女兩套造型＋一間共用小屋約 5～9 天收齊。這是規劃目標，仍須一般玩家試玩校準，不保證每局收入。

| 節慶 | 每日場次 | 每套造型 | 共用小屋 | 男女全套總價 | 完成獎勵 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 萬聖節 | 3 | 240 | 300 | 780 | 無，依找到的幽靈計算 |
| 聖誕節 | 5 | 200 | 300 | 700 | 10 聖誕襪，另計禮物所得 |
| 春節 | 3 | 280 | 380 | 940 | 擊退大年獸給 5～10 紅包；大年獸每次命中 0～1 紅包 |
| 兒童節 | 3 | 220 | 320 | 760 | 8 彩票，另計射擊所得 |
| 端午節 | 3 | 240 | 300 | 780 | 依名次發 55／35／25 香包，不另加問答或完成獎勵 |

完成獎勵也納入畫面合計與單次入帳；體驗模式只展示，不發正式貨幣。中途退出沒有完成獎勵。

春節命中門檻提高為 10／50 下後，每次命中的紅包規則維持原設定，因此收入與完成時間增加。依首關 16 紅包的原模型假設，每局平均約 78.5、每日約 235.5，940 貨幣全套約 4 天；此版本尚未重新壓回每日 120～150 的目標。

新增節慶先列：玩法、完成條件、遊玩時間、每日場次、獎勵來源、失誤扣除，以及新手／一般／熟練表現假設。以「男女全套總價 ÷ 每日平均收入」檢查收集天數，再各收集至少 10～20 局試玩資料，記錄遊戲模式、完成時間、各來源收入、失誤扣除、合計與完成率，修正假設。完成局與中斷局分開統計。

`node balance-festivals.cjs` 會依現有價格與明列的表現假設產生模擬報告，供新增遊戲比較；報告不是人類玩家實測結果。

## 主頁與小遊戲訊息

聖誕節題庫獨立於 `xmas/questions.js`，每局抽兩題且不重複，不使用主系統共用題庫。格式為 `[題目, [選項一, 選項二, 選項三], 正解索引]`，正解索引從 0 開始。題庫載入失敗、格式錯誤或少於兩題時禁止開始且不扣次。新增題目後需連同遊戲發布題庫檔案。

每局 URL 帶 `session`。雙方檢查訊息來源、origin、session；主頁另核對遊戲鍵。

1. 小遊戲 `fsGameStart` → 主頁檢查並扣次 → `fsGameStarted`。
2. 完成畫面後 `fsGameResult`（`completed: true`、整數 `earned`）→ 主頁單次入帳 → `fsGameSettled`。
3. `fsGameReplay` 建立新局；`fsGameClose` 關閉 iframe 並返回正確入口。

這是既有前端存檔架構的局次核對，不是伺服器反作弊驗證。

## 端午節

2026-11-09 定案：兩關玩法、玩家中央船位、大字操作、粽子與香包圖示、AI 追趕難度，以及兩關各八段旋律與競速強鼓版本均已接入遊戲。
遊戲 CSS 與 JS 使用定案版本參數 `20261109-1`，以便重新進入時載入最新樣式、規則與配樂。

正式活動鍵為 `duanwu`，遊戲目錄為 `dragonboat`；透過 HTML 的 `data-game-key` 對應共用訊息流程。
獨立題庫 `dragonboat/questions.js` 使用 `[題目, 三個選項, 正解索引]`，目前 20 題。
每輪洗牌優先不重複，題庫用完重新洗牌且不緊接重複上一題；選項另行洗牌並保留正解。
每題 5 秒，答對 +1、只有答錯 -1、最低 0；PASS 立即換題且不扣分，逾時未答自動換題且不扣分。
總時限優先，30 秒時未完成當題不扣分。
完整問答成績保留，攻擊粽子最多 5 顆；題庫或素材載入失敗禁止開始，不扣次。

第二關目標為一般約 40 秒、熟練者約 15～20 秒。龍舟基準 25 m/s（無干擾 40 秒）；
每 1.4 秒一次節拍，中段金色有效區域占 44%（約 0.62 秒）。連續成功划船依序提升至 35／50／70 m/s，
每次提升維持 1.6 秒；超過 2.1 秒沒接上或在錯誤區域操作會重置連續次數。
同一節拍不允許連點累積加速；AI 基準也是 25 m/s，平時每次節拍有 35% 機率短暫提升至 32 m/s、維持 0.75 秒。
玩家連續划船升至 50 或 70 m/s 時，AI 進入 4.2 秒追趕節奏：紅舟 90%、藍舟 82% 機率抓準節拍，
分別以玩家該段加速速度的 103%／98% 划船，持續 1.6 秒。只改變划船速度，不改寫剩餘距離；水流與攻擊效果照常套用。
時間不是強制倒數，任一船先抵達就立即結算。`node balance-dragonboat.cjs` 可檢查不同節奏表現的完賽時間；這是程式模擬，仍須真人試玩校準。
三船每約 4.5 秒各自隨機遇到順流（140%、2 秒）或漩渦（65%、1.5 秒），首次在 3 秒出現。
水流效果取代前一水流，不累乘；攻擊減速（50%、1.5 秒）另乘，受擊起 2.5 秒免疫再次攻擊。
划槳兩側有「攻擊紅舟／攻擊藍舟」按鈕，亦可直接點紅／藍舟；每次消耗一顆粽子攻擊，保護期間不消耗。
按鈕顯示保護狀態與粽子是否用完；AI 各 3 顆，會隨機攻擊未受保護的另一艘船。
不設實體碰撞障礙；任一船抵達即凍結全場，依剩餘距離排名，距離相同並列且按並列名次發獎。
隱藏分頁或離開確認不暫停，切回時按實際經過時間補算。綠舟為玩家，固定在中央；紅舟在左、藍舟在右，紅藍為 AI。
上方距離卡與下方「攻擊紅舟／划船／攻擊藍舟」均依相同左右順序排列。

素材原圖與透明圖集在 `dragonboat/img/`。透明圖集以內建 imagegen 產生，提示詞為：
「去除元件圖彩色背景為透明，保留原位置、完整造型、顏色與文字，不新增或重排元素」。
遊戲使用原背景圖與自透明圖集裁出的三艘龍舟。

主頁活動圖示與結算共用此圖，貨幣數量由遊戲及主頁流程計算，與圖案來源無關。
`dragonboat/music.js` 參考兒童節的 Web Audio 合成方式，以五聲音階搭配竹笛風格音色、撥弦合成、低鼓、鑼鈸與輕打擊。
兩關各有八段主題旋律與不同編排；問答以笛聲主題、撥弦回應、舒緩橋段與回歸段落構成。
競速使用獨立短句主題、快速撥弦、低八度回應、和弦掃弦及段尾鼓花，以鼓樂主導；主鼓每 1.4 秒配合划船節奏，伴奏細分不改變操作速度。
競速主鼓加強重音、鼓皮起音與中低頻共鳴，輔鼓與段尾連擊增加層次，讓手機喇叭也較易辨識鼓點。
這些為程式合成音色，非真實樂器錄音。`node render-dragonboat-audio.cjs` 可輸出問答 32 秒、競速 24 秒試聽檔並檢查音量峰值。
按開始後播放，結算與離開時停止；背景音樂及操作音效皆接共用 `FSGame.output`，聲音按鈕同步控制靜音。
操作區使用大字「划船／攻擊紅舟／攻擊藍舟」；攻擊無法使用時保留清楚的主標籤，並在副標顯示保護或粽子狀態。

## 驗證

在專案根目錄執行 `node verify-festivals.cjs`。需要 Playwright 與 Microsoft Edge；可使用 Codex 隨附的 Playwright。
端午另執行 `node verify-dragonboat.cjs`，檢查競速、速度效果、免疫、問答、手機 HUD、入帳、再玩、離開與體驗。
測試以替代主頁狀態檢查四個實際遊戲 iframe，包含手機 HUD、時間、命中次數、入帳、再玩、體驗扣款及離開；截圖存於 `artifacts/festivals/`。

## 共用活動清單

活動名稱、狀態、每日次數與兌換價格集中在根目錄 `festival-config.js`。主頁、星宮、後台共用；日期與原商品販售規則仍由 `index.html` 管理。
新增遊戲須先維持 `coming-soon`，補齊正式設定及測試後才改為 `ready`。請勿只因日期到達就開放未完成的遊戲。
共用畫面準備完成後發送 `fsGameReady`；主頁收到後移除載入畫面。載入失敗時可返回、不扣次。

`node verify-integration.cjs` 檢查共用清單、COMING SOON、載入失敗返回、過期兌換、幣別轉換通知、主頁 HUD 與後台清單；雲端採模擬 Firebase，不接觸正式資料。截圖在 `artifacts/integration/`。
七夕、中秋、國慶已接入正式扣次／入帳與星宮體驗。中秋關卡為嫦娥奔月後接三軌玉兔；正式每日 3 次、每套造型 240 月餅、共用小屋 300 月餅，正式日期沿用主頁。必要對接檢查執行 `node verify-moon-host.cjs`，素材與玩法見 `moon/README.md`。國慶規則與對接見 `doubleten/README.txt`，驗證執行 `node verify-doubleten.cjs`。七夕發布檢查執行 `node verify-seven-release.cjs --release`。
