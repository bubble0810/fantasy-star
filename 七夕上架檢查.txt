正式發布仍需完成的項目
1. 決定正式每日場次與兌換價格，檢查現行每局 2～7 紙鶴是否符合 FEST 收集天數目標。
2. 接入共用流程，先 fsGameReady，再由主頁核可 fsGameStart 才開始並扣次。
3. 完成後顯示共用「遊戲結束」，再 fsReport，等待主頁確認才開放再玩／返回。
4. 核對 origin／來源／session／qixi，確認同一局重送不重複發獎。
5. 再玩由主頁建立新 session；正式返回活動頁、體驗返回星宮、獨立試玩返回 ../../index.html。
6. 加入圖片／配樂載入失敗的開始阻擋及可返回畫面，避免失敗仍扣次。
7. 將七夕正式／體驗的完整流程納入整合測試後，才把 status 改成 ready。
不能只改 status 就上架。

檢查指令（在主資料夾執行）
node verify-seven-release.cjs
  檢查路徑、大小寫、名稱對應、主頁／後台版本及專案子路徑載入；列出正式發布阻擋項。
node verify-seven-release.cjs --release
  正式發布檢查。未完成上列條件時會以失敗結束，這是預期的防誤上架行為。
node verify-seven.cjs
  驗證七夕玩法、進度、靜音、再玩、離開及手機排版。
node verify-integration.cjs
  驗證主站／後台及開發中入口不扣次；使用模擬 Firebase，不讀寫正式玩家資料。
node render-seven-audio.cjs
  產生試聽檔並檢查削波。
